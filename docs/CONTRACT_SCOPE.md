# Hedgefun 合约要做的事（内部文档）

写给新加入的人。这份文档回答一个问题：**我们的合约到底要做什么、哪些已经做了、哪些在做、哪些永远不做。**
它不是接口文档（那在各目录的 `abi/` 和源码注释里），也不是部署记录。日期截至 2026-09-26。

## 一句话

Hedgefun 是 Robinhood Chain 上的**策略型 meme 股票 launchpad**。创建者填一张表，得到一个固定供应量的
代币、一个按公开规则交易某只代币化股票的 treasury、和一个 `<代币>/<股票>` 的 Uniswap V4 池。交易税喂养
treasury，treasury 的已实现利润回购代币并燃烧。发射之后没有 keeper、没有可改的参数、没有人能提款。

链上能核对的承诺（叙事只能说这些）：每笔卖出把真实股票送进一个没有提款函数的 treasury；流动性永久锁定；
供应量只减不增；没有止损的规则永远不会低于成本卖出一个 lot。**不能说的**：规则跑赢持有股票（回测里 193 只
股票大多数在 1.00 附近）、任何 NAV 或每币价值（没有任何东西可赎回）、以及 "ETF" 和 "基金" 这两个词。

## 三条产品线，别混

| 线 | 是什么 | 状态 |
|---|---|---|
| **Launchpad V1** | 上面那段话。`contractV1/` | 2026-09-22 主网上线，18 只股票已上架，Safe `0x2910…` 持有全部 owner 权限 |
| **Launchpad V2** | 先在 bonding curve 上募集真实股票，再原子毕业进 V4 池 + treasury；treasury 可选策略类型，含策略引擎。`contractV2/` | 2026-09-28 合进开发仓库 main（`e2b32c7`），代码在 [PR #1](https://github.com/0xHedgeHood/Hedgefun-trade/pull/1)。**未部署，也还不能部署**，见下面的部署门 |
| **Delta-neutral 做市 / StockLend** | 集中流动性 LP 加永续对冲，以及股票借贷。不在这个仓库 | 运营者试点，与 launchpad 独立 |

下面只讲前两条。

## V1：已经上线的合约必须做到的事

### 发射时

- **不需要资本。** 全部供应量作为单边流动性进 V4 池，任何人（包括我们）都撤不出来。V4 把仓位绑在
  `(msg.sender, tickLower, tickUpper, salt)` 上，调用方是工厂自己，而工厂字节码里没有第二个 `modifyLiquidity`。
  fork 测试把精确的 tick 和 liquidity 交给攻击合约，撤出仍然 revert。
- **报价即承诺。** `launch(q, terms)` 里的 `terms` 是 `predict(q)` 返回的哈希，任何默认值在中途变了就 `Restated`。
- **创建者能选的**：名字、符号、一只**已上架**的股票、税率、自己在股票侧税里的分成、规则参数
  （`tp1`、`tp2`、`dip`、`stop`、`lotBps`）。**不能选的**（每一项都曾是抢买家钱的路径）：股票的 oracle 和交易池、
  协议分成、供应量、开盘价、执行边界。
- **可选的发射费**，三种币之一（原生币、USDG、或者就是发射对的那只股票）。
- 想让 treasury 第一天就有钱，走 `HedgeFunLaunchRouter`：一笔交易内发射、创建者自己的第一笔买入（照常收税）、
  给 treasury 第一个 lot。这笔钱单向，创建者也拿不回来。

### 交易时（`HedgeFunHook`，所有策略共用一个地址）

- 只有一个 hook 地址，因为 Uniswap 的路由白名单按 hook 地址审。代价：发行方拉黑这一个地址等于拉黑所有策略。
- **买入税收代币，全部燃烧**，没人拿到。前 3 秒是开盘窗口：99% → 66% → 33% → 平税，把首块延迟竞赛变成 3 秒
  的降价拍卖。它不防耐心的机器人和多钱包，也不声称能防。
- **卖出税收股票**，拆成：sweep 调用者小费、协议 `protocolBps`、创建者 `creatorBps`、余下进 treasury。
  协议和创建者的全部收入只来自股票侧的税。
- 卖出税率在发射和每次回购后**尖峰**，按秒线性衰减回平税（这条链 0.1 秒一个块，按块衰减看不见）。
- exact-output 只接受平税买入（税按 `r/(1−r)` 计），其余 exact-output 拒绝。

### 规则（`HedgeFunTreasuryBase` + `HedgeFunTreasury`）

- 税进来按 oracle 价记成一个 **lot**。lot 在 `cost+tp1` 卖一半，`cost+tp2` 卖剩下的；可选止损（默认关）亏本卖、不燃烧；
  USDG 储备在 `lastSale−dip` 回买。**lot 永远不低于自身成本卖**，所以已实现利润不会为负。
- 只有**本金**变成 USDG；**利润**留在股票里，在该策略自己的池子里回购代币并燃烧。
- 股票腿在 **V3** 上交易（`PoolTrader`），10 分钟 TWAP 校验现货。代币自己的池子永远是 V4。
- 卖出可以**部分成交**：按 `oracle × (1 − maxSlippageBps)` 算池深，卖多少 lot 减多少，一点没卖就 revert。
  `sellChunkUsdg` 限制单次报价的量（每只股票由 owner 按实测深度定）。
- 交易日历（24/5）关闭时：走池子自身均值的封闭市场路径，一小时一个 chunk，`bandCeiling` 每只股票冻结。
- `setVoteDelegate`：treasury 的 owner **只能**指定投票委托，动不了任何资产。这是给未来留的舱口（股票代币可升级，
  treasury 不可），今天链上没有任何东西可投票，前端必须这么说。

### Owner（协议 Safe）对已发射策略只能做四件事

1. 通过交易日历**停掉规则**（强制关一天，动不了价格）；
2. 移动协议**自己**的收款地址（`setProtocol`）；
3. 移动**消失的创建者**的收款地址：链上提议后 14 天才能接受，创建者一个 `vetoCreator` 就否决并锁 180 天；
4. 指定 treasury 的投票委托（见上）。

其它一切（上架、默认值、gate、launcher 白名单、是否公开发射）只影响**未来**的发射。`renounceOwnership` 已禁用。
代币页面（logo、描述、链接）属于发射时的创建者，协议无权碰。

### 上线前必须过的门（每次发布都一样）

Safe 上有硬件钥匙；一笔真实的 Safe 交易；CI 账单正常；每个上架池跑过 basis check；部署演练在最终代码上重跑；
hook 源码在 Blockscout 验证；`setLauncher(launchRouter, true)` 签好；hook 部署并绑定**之后**再提交路由白名单。

## V2：已合并、未部署的合约要做到的事

V1 的短板：treasury 从 0 起步，只能靠卖出税攒股票；毕业后的池深由开盘价和全部供应量决定。V2 改成**先在以股票
计价的 bonding curve 上募集真实股票，再原子毕业**。V2 是独立部署（新工厂、新 hook 地址、新一轮路由白名单审核），
V1 已发射的东西永远不变。

1. **Curve 募集，不垫资。** 每个 launch 一个 `HedgeFunBondingCurve`，固定乘积 `K = S × V`，虚拟储备 `V` 永不可支出，
   买家用股票买入，真实储备就是毕业资本。没有共享资金池、owner 提取、救援或取消。
2. **原子毕业。** 触及终点价的那笔买入调 `graduateCurve()`：初始化 V4、注入流动性、`wire()` 启动 treasury。
   任何一步失败整笔回滚。公开 `graduate(id)` 不能提前、不能动别的 curve。
3. **资本二分，LP 锁死。** 真实储备按 `lpBps`（每只股票 owner 设，发射时冻结，默认 50%）分给 V4 全区间仓位和 treasury。
   `V2LiquidityVault` 只能收手续费。V4 LP 费必须非零（≤0.30%），股票侧费进节奏化回购，FUN 侧燃烧。
4. **一个原子的 `execute()`。** 先处理到期止损（含部分成交），有到期止损时禁止抄底，再复核价格才可能买。
   V1 的三个入口在 V2 上 revert。止损后第一次重入要等 600 秒、更新的报价、更深的下跌。这是 fork 回放里修掉的真实 bug。
5. **任意 ERC20 / 原生币进出。** 最多 3 跳 V3 到股票，再进 curve 或 V4。两个独立最小值分别保护两段；
   部分成交必须显式允许，退款以**股票**退回。收费转账代币直接拒绝。
6. **策略类型可插拔、发射后冻结。** 类型进 CREATE2 salt，所以进 `terms`。kind 0 是 V1 的规则；kind 1（纯回购）
   可选；**策略引擎**（#91）是第三种，下一节单独讲。
7. **3 秒开盘税接到 curve 上**，无创建者豁免。仍是摩擦不是保护：市场场景测试在第 1、2 秒找得到有利可图的三明治。

**V2 部署前必须决定的**：开盘狙击的经济问题（产品决策，不是代码开关）；每只股票的 `lpBps`（毕业后池很浅，
算例里卖 1% 流通量跌 17%）；工厂离 EIP-170 只剩 25 字节、`CurveDeployer` 只剩 12 字节，V2 的任何修复都得放在别处；
第三方审计。

### V2 的策略菜单（2026-09-27 决定）

kind 0 的规则只有一条再进场路径（跌回上次卖出价以下），单边上涨里卖完就出局：推演里 +3%/天时第 16 天毕业
lot 全部卖光，90 天后剩死拿的 0.51。解决它的地方不是给 kind 0 加参数，是让创建者在发射前选**策略类型**
（`setStrategyKind`，进 CREATE2 salt 所以进 `terms`，发射后冻结）。第一版给四种，每种两三个数字：

| 类型 | 做什么 | 卖飞吗 | 在哪 |
|---|---|---|---|
| 区间 | kind 0，止盈/抄底 5%/5%，实测横盘波动里最好（1.07 到 1.10） | 会 | #84 |
| 再平衡 | 股票占总值 targetBps，偏出 deadband 修一刀，有冷却、单笔和日换手上限 | **不会**，永远持有目标比例；但每次上涨都削一片，见下一节 | #91，已合并 |
| 钻石手 | 只持有股票，回购只靠 LP 费（ROADMAP 第 14 项，kind 0 把止盈设成不可达） | 不卖 | 配置 |
| 全回购 | kind 1，募集来的股票按节奏买 FUN 烧掉 | 不卖股票 | 已合并，可选；部署时要注册它的代码块 |

还要给 kind 0 加"离场超过 N 天按市价买回 x%"的时间再进场，几行代码。追踪止盈维持 ROADMAP 的拒绝。

**#91 必须和 V2 一起发。** 引擎 treasury 的构造签名和 kind 0 不同，现有 `registerKind` 装不下，而工厂对
deployer 的引用是 immutable：按 #84 部署的工厂以后加不上 #91，要加就是新 deployer、新工厂、新 hook 地址、
再走一遍路由白名单。其它三种都能用 `registerKind` 后补。#91 的合约代码 860 行（引擎 409、deployer 260、
policy 107、接口 81），其余 5,000 多行是 ABI 导出和测试。2026-09-28 两个都已合进 main，round 4 审计覆盖了合并后的代码。

### 策略引擎（#91）怎么工作

kind 0 把"什么时候买卖"写死在 treasury 里。引擎把它拆成两半：**policy 只做决定，treasury 只管钱**。

```
       keeper（任何人）
            │ execute()
            ▼
  ┌──────────────────────────┐   STATICCALL，限 gas，   ┌──────────────────┐
  │ HedgeFunV2EngineTreasury │ ────────────────────────▶│ policy（无状态）  │
  │  持有股票和 USDG          │   返回固定 160 字节：    │  例：再平衡       │
  │  自己校验一切            │ ◀──────────────────────── │                  │
  └──────────┬───────────────┘   持有 / 买 / 卖 + 数量  └──────────────────┘
             │ 只能 swap 进上架的 V3 池
             ▼
       V3 股票/USDG 池
```

- **policy 能说的只有三件事**：持有、买股票、卖股票，加一个数量和下一步的 nonce。它选不了池子、路由、收款人、
  授权，也拿不到任何钱。它是 STATICCALL，改不了状态；返回长度不对、耗光 gas、回奇怪的值，统统拒绝。
- **treasury 不信 policy**，每次执行都自己重新检查：配置哈希和 nonce、policy 的运行时代码哈希、喂价新鲜和池价偏差、
  这个 policy 注册时声明的能力（只卖的 policy 不能买）、冷却时间、方向是否和 deadband 一致、单笔上限、当天累计换手、
  实际成交量（成交太少整笔回滚，冷却和 nonce 都不前进）。
- **配置在发射前承诺**。创建者给自己将要发射的 `(symbol, creator, nonce)` 设一个固定宽度的 `EngineConfig`，
  它被拼进 treasury 的 initcode，所以改了配置 treasury 地址就变，`terms` 就对不上，发射 `Restated`。发射后永远不能改。
- **注册表只增不减**。工厂 owner 注册新的引擎类型和 policy；禁用一个 policy 只挡住新发射，已经发射的 treasury
  把 policy 身份和上限存成 immutable，不受影响。
- **期权留了位置但没开**。能力位里预留了写期权、买期权、行权、结算，但这个现货引擎一律拒绝；以后要做期权是另一个
  单独注册的引擎版本，有自己的保证金和到期规则。

**第一个 policy：再平衡**（`V2RebalancePolicy`）。三个数字加两个上限：目标比例 `targetBps`（股票占 treasury 总值）、
容忍带 `deadbandBps`、冷却时间；单笔最多 `maxTradeUsdg`，一个 UTC 自然日最多 `maxDailyTurnoverUsdg`。股票占比跑出
目标 ± 容忍带，就朝目标修一刀，一刀不超过单笔上限。

**它解决了什么、没解决什么**（round 4 审计的 econ lane 用同一个单边行情模型，90 天，$20k treasury）：

| 行情 | kind 0（30/60） | 再平衡 目标 50% 带 5% | 再平衡 目标 80% 带 5% |
|---|---|---|---|
| +3%/天 | 0.54 | 0.47 | 0.76 |
| +1%/天 | 0.84 | 0.77 | 0.92 |
| 横盘 4% 波动 | 1.04 | 1.07 | 1.05 |
| −1%/天 | 1.03 | 1.40 | 1.16 |
| −3%/天 | 1.03 | 3.17 | 1.62 |

数字是以股票计、相对"死拿"的倍数（含已烧掉的部分）。

- 它**不会卖飞**：永远持有目标比例，没有"卖完出局"这个状态。
- 但它在每一次上涨里都削一片，所以**以股票计在上涨里比 kind 0 还差**（目标 50% 时 0.47 对 0.54）。想跟涨要把目标设高，
  80% 时明显好过 kind 0。
- 横盘波动里略好于 kind 0，下跌里明显好于 kind 0。
- **它的收益现在不喂回购**：卖高买低赚的 USDG 留在储备里，只有 LP 费进回购，所以任何行情下只烧约 0.19% 供应量，
  kind 0 在 +3%/天时烧 2.2%。要不要把收益按比例分给回购（改动几百字节，引擎还剩 3,002 字节）是**待定的产品决定**。

**round 4 审计对引擎的结论**：0 Critical、0 High。钱只能流进上架 V3 池的 swap 回调，policy 什么都拿不到，swap 内重入
被拒，配置到 `terms` 的承诺链成立。要修的都是"该挡没挡"的配置检查和没被测试钉住的守卫，修复在开发仓库的
`fix/v2-round-4` 分支：

- 单笔上限小于最小成交量的配置能发射，结果是一个永远执行不了的 treasury；`setEngineConfig` 不做构造函数的检查，
  `predict` 会报出一个发射时失败的配置。修成一个函数两处都跑。
- **下限**：容忍带 ≥ 2 ×（滑点 + 池费），和 V1 的止盈/抄底下限一致；冷却 ≥ 600 秒；日换手 ≤ 24 × 单笔；目标 20% 到 90%。
  没有这些，1 bp 的容忍带会在每一次 0.5% 的喂价更新上交易一次。
- **三明治**：`execute()` 谁都能调、不付 bounty、下单时间可预测。攻击者把池价压到喂价偏差门边上再调用，treasury
  每次多付约 49 bp。在 0.30% 和 1% 的池上攻击者是亏的；在 0.05% 的池上单笔超过池子每 1% 深度的 10% 就有利可图，
  今天的 GME 已经过线。修法是 owner 给 0.05% 的上架设 `sellChunkUsdg`，0 字节。
- 日换手按 UTC 自然日算，午夜前后几分钟能做两倍。按自然日还是滚动 24 小时，部署前要定。
- 毕业时引擎拿到的全是股票、没有 USDG，目标 50% 就会在毕业后几分钟内把一半卖回刚被买空的池子。要么文档写明，
  要么把目标起点设成毕业时的构成。

### V2 部署参数（讨论中，Defaults 还没上链）

| 杆 | 现在 | 讨论中 | 为什么 |
|---|---|---|---|
| 交易税（创建者选） | 1% 到 15% | **上限 ≤ 5%**，范围待定 | pons 链上 10.6 万个发射：5% 以内毕业率不随税变（都约 1%），同一创建者的成交量也不变；超过 5% 毕业率掉到 0.18%、成交量减半。5% 以内创建者每次发射的收入随税翻倍。treasury 由毕业资本喂，税只剩发钱和燃烧 |
| 卖出税分配 协议/创建者/treasury | 20 / 10 / 70 | 30 / 35 / 35 | treasury 已有毕业资本；创建者收入决定有没有人来发射 |
| V4 LP 费 | ≤ 0.30%，必须非零 | 0.30% | 不靠税的燃烧飞轮 |
| saleBps | 80%（$10k FDV 募 $40k） | 44% 到 60%（$8k 到 $15k） | 单笔募集对 V3 池冲击压进 50 bp；早期倍数 25x 降到 3x 到 6x，狙击利润同步缩 |
| keeper bounty | 花费的 0.5% | 固定补偿 + 0.05% | gas 几分钱；按比例惩罚交易多的规则，且现在付给自己 |
| listing gate 偏差/滑点 | 50 / 100 bp | 深池 30 / 45 bp | 防操纵的闸不能去掉；收紧只为让细规则过下限 |
| 3 秒开盘窗口 | 99 → 66 → 33 → 平税 | 保留 | 摩擦不是保护 |
| 上架 | 18 只 | 去掉 INTC；USAR、AMD、GME 缩募集或不上 V2 | 审计 M-2/M-3：毕业需要的股票量要 ≤ V3 池在偏差门内能给的量，加成上架规则 |

税率的依据是 pons 的链上数据（开发仓库 #93，`docs/research/PONS_TAX_ELASTICITY.md`）：同一条链、同一批股票，每个发射付 1% 基础费，创建者再加 0 到 10%。2026-09-16 到 09-28 的 106,631 个发射里，**5% 以内税率不预测毕业**，同一创建者在 1% 和更高税率下的成交量中位比是 1.09x 和 1.02x；**超过 5% 两者都崩**。数据支持把上限设在 5% 以内，但不支持非得压到 1% 到 2%。注意：税是创建者选的不是随机分配的；pons 把创建者税还给创建者，刷量便宜；只量了 curve 阶段。

同一份数据还纠正了一件事：pons 的 3 秒开盘狙击费在链上是**生效的**（13.5 万笔交易付了 99%、7.18% 或 1.19%），之前按仓库里存的旧源码以为它没接上，是错的。

## 永远不做

owner 或创建者提款；常设赎回；创建者可改参数；追踪止盈（需要一个只在有人调用时才动的链上最高价）。

## 工作规矩

- 永远不签名、不广播交易。准备好命令或 Safe Transaction Builder JSON 交给人。
- 发射后的策略不可变，所以**任何舱口必须在出生时就在**，事后加不上。这是 V1 为什么塞进七个 v2 候选项的原因。
- `forge test` 在 fork 模式下跑；改完源码或编译器先看 `forge build --sizes`。
