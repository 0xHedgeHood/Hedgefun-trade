# V2 本地经济实验台

从仓库根目录运行：

```bash
python3 -m lab.server
```

然后打开 <http://127.0.0.1:8765>。服务只监听 `127.0.0.1`，不连接钱包、不签名、不广播。也可用 `--port 8766` 指定端口。

页面包含四种**不能混为一谈**的结果：

1. **参数模拟**：调整 LP/国库分配、曲线售出比例、虚拟股票储备和买卖压力。`lab/model.py` 以连续恒定乘积近似 V4 满范围池，计算毕业时真实储备、FUN 配对/销毁、独立买入和卖出情景，以及推动现价 20% 所需占用资金。它包含静态 LP 费与普通平税的近似，但不模拟 Hook 的动态卖出 spike、外部路由/套利、国库策略或回购净利润。累计曲线买入税按**单向售出至毕业**估算；若毕业前有人卖回再买，累计销毁量更高，卖压基数也会变。它不是链上交易报价，也不是攻击者净收益。图表刻意不计手续费以单独展示深度效应；指标卡的买单成交差包含 LP 费和 Hook 税。
2. **固定区块 Fork**：按钮运行 `test/V2LiveVenueFork.t.sol`，在 Robinhood Chain 区块 `70,786,980` 的本地 EVM 状态中使用实际 USDG/GME V3 池和 V4 PoolManager。V2 合约与买卖仅在临时 Fork 内执行。测试刷新喂价时间戳并使用 `AlwaysOpen` 日历，因此验证的是固定池状态下的交易与毕业路径，不验证该历史区块原始喂价新鲜度或开市约束。当前候选合约的 LP 比例默认 **50/50**，owner 可按股票用 `V2TreasuryDeployer.setLpBps` 调整。运行 50/50 时核对原源码；运行其他比例时，执行器在系统临时目录复制必要文件，只改副本 `V2TreasuryDeployer` 的 `DEFAULT_LP_BPS` 后编译并运行同一 Fork 测试。变体结果是实验结果，**不是 #78 合约当前可配置的行为**，也不会修改工作树或广播。
3. **多人交易压力测试**：四个按钮分别运行抢买、抢卖、买卖交错和开盘狙击的 Foundry 测试，使用真实 V2 合约、Hook、V4 PoolManager，股票和喂价是测试替身。它不使用 Robinhood Fork。交易在同一时间戳逐笔排序，并对照反向顺序；结果含实际成交与税费。详见[实验记录](../docs/V2_MARKET_SCENARIOS.md)。页面中的 LP 分配等输入**不影响**这四个固定场景。
4. **统一价格开盘实验**：可输入机器人与用户的 STOCK 买单和用户最多滑点，比较第 1 秒逐笔曲线、3 区块直接聚合买单、以及把清算价与批后现价对齐的研究模型。用户按各机制独立报价设置最低**净** FUN 到账，低于门槛则整笔退款；没有部分成交。还显示保留现有 66% 开盘买税时的同批结果，以及机器人独占开盘批次、用户下一批买入的风险。三种主对照税率不完全相同：统一价方案默认 10% 普通买税，现行第 1 秒为 66% 买税。此项纯数学模拟，**不是链上 Fork、已实现的合约功能或可执行报价**。详见[实验记录](../docs/V2_BATCH_OPENING_EXPERIMENT.md)。

运行校验：

```bash
python3 -m unittest discover -s lab -p 'test_*.py' -v
RH_FORK=1 forge test --mc StrategyForkTestV2LiveVenue -vv
```

Fork 执行需要可用的 `robinhood` RPC 别名（见仓库的 `foundry.toml`）与 Foundry。按钮只运行白名单中的测试，禁用 FFI，限制执行时间；失败和超时会在页面显示。页面只从同源回环地址接受模拟与 Fork 请求。除 LP 比例外，页面里的其他输入只影响离线模型；Fork 交易脚本的买卖规模当前固定。

多人压力测试不需要 RPC。四个场景也只运行白名单测试、禁用 FFI，并在隔离的编译目录执行。与 Fork 实验共用单任务锁，避免同时运行两个耗资源的 EVM 实验；页面提供 Foundry 执行日志的末尾 12 KB。

选择最终分配比例时，还需要真实交易规模、净攻击收益和国库回报情景。数学模型可以排除明显浅的方案，不能单独批准部署。
