# V2 简单循环：冻结行情对照

新增入口使部分卖出后的现金能在价格恢复时回补，但这组历史数据没有证明它普遍提高收益。96 个固定窗口配对中，每日一次模式有 17 对改善超过 0.05 个百分点、11 对变差超过 0.05 个百分点、68 对基本不变；差值中位数为 0。这里只判断功能闭环，不将新增模式选作默认或宣称它减少所有“卖飞”。

## 冻结输入与对照

- `data/v2-cycle-prices.json` 保存此前已取得的 NVDA、TSLA、GME、AAPL 真实日收盘，分别 689 根，2024-01-02 至 2026-09-30。保留来源 URL、取得时间、公司行动记录和原始捕获文件 SHA-256；本次没有联网下载。
- 比较原 Kind 0 与简单循环，使用相同 6 套固定参数：已发测试样例、宽止盈、区间网格、窄止盈无止损、12% 止损、高门槛持有。它们是参数模板，不是 6 个独立 policy。此次不改变 Kind 2。
- 固定窗口为最近 21、63、252 个交易日和 2026 YTD。分别取 22、64、253 个收盘；YTD 从 2025-12-31 基准开始。基准只入账，下一交易日才允许动作。每个窗口独立从 10,000 USD 等值股票、现金 0 开始，并非重建已发行 treasury 的历史余额。
- 96 个固定配对，另有 96 个同价多次调用敏感性配对；240 个滚动配对为最近 252 日内、每隔 21 日开始的 10 个 63 日窗口。滚动窗口彼此重叠，不能将改善次数解释为独立胜率。

## 与合约保持相同的循环语义

1. 保留 `stop > profit > buy` 顺序、最高成本止损优先、TP2 优先于其他 lot 的 TP1、每次 2,000 USDG 等值股票 chunk、TP1 未完成数量和实际成交记账。
2. 只有实际出售股票按认证价格计值至少 5 USDG、USDG 输出为正的销售才创建/更新恢复等待。止盈看实际出售的本金股票，不把拨往回购的利润股票算作销售。新的等待锚点独立于原 `lastSalePrice`。
3. 回升买须有等待状态、至少过 600 秒、股票报价更新时间严格更新、当前价达到独立卖出锚点的 `1 + dipBps`。复用 `dipBps`，没有另加恢复阈值配置。
4. 回升预算为 `min(现金 × lotBps, sellChunkUsdg)`，先预留执行奖励。新 lot 成本是实际 V3 花费 / 实际收到股票，含成交成本、不含另付奖励。任何成功跌买或回升买均消费等待状态；随后原跌买阶梯继续工作，新的实际销售才重开回升入口。
5. 原止盈后跌买不加新的等待限制，也不增加 chunk cap；原止损后跌买仍要求 600 秒、新报价及更低档位。后来的小额止损即使不足以重设恢复锚点，也重新约束最新止损的冷却和报价更新。恢复入口独立保存这项约束，后续小额或零成交止盈不能清掉它；原止盈后跌买仍保持原语义。
6. 关闭市场时足额止盈会取消旧恢复等待；小额销售、仅划利润、零输出不创建新等待。失败或不足最小成交金额的买入不消费等待，也不更新 lot、现金或买入参考价。

主历史样本把每个收盘视为新的 live、健康股票报价；不会假装日线包含 10 分钟内的真实报价过程。冷却、旧报价、小额后续止损、关闭市场销售以及部分/失败成交由合成测试单独覆盖。

## 成本和收益口径

每次 V3 成交损耗为测试 listing 的费率加假设滑点 10 bps：NVDA/GME/AAPL 共 15 bps，TSLA 共 40 bps。执行奖励 50 bps：止盈从利润股票扣，止损从 USDG 输出扣，买入按实际花费另付。回升 cap 为扣奖励前预算，完全成交现金减项为预算 × `(1 - 0.005²)`。没有增加税收、LP 费或捐赠输入；USDG 固定为 1 USD。

组合净值 = 策略库存股票 × 收盘价 + 尚未花费的回购股票 × 收盘价 + 现金。收益相对窗口初始净值，最大回撤相对此前净值峰值；持有基准为同一初始股票数量。回购股票仍有股价敞口，策略库存为 0 并不一定代表无股票敞口。本结果不包含 FUN 兑换/销毁、FUN 价格、股息、真实 V3 深度和 gas；它不是 FUN 持有人回报。

## “卖后上涨”与执行频率

`salesThenRise20 / eligibleSales20` 只在销售拥有完整后续 20 交易日时，统计最高后续价比卖价上涨至少 10% 的销售调用数量。未来价格只用于事后标签，不进入交易决策。它不检查期间是否已经低价买回，也不表示该销售是错误操作；同日多个 chunk 仍分别计数。分母为 0 表示样本不足，不表示没有卖飞。

窄样例 252 日：NVDA 从 1/9 变为 7/27，TSLA 从 10/12 变为 12/23，GME 从 4/12 变为 6/24，AAPL 从 1/7 变为 5/16。闭环增加销售及入场机会，所以该标记的原始数量不能直接作为改进目标。

同价多次调用假设每笔之后仍可按同一收盘价足额成交，并继续通过池价健康检查，仅表示执行频率敏感性。96 对中 15 对改善、11 对变差、70 对基本不变。TSLA 的 12% 止损模板 252 日在这一理想模式下，原收益 -9.61%，循环 -26.86%，差 -17.26 个百分点；不能只挑每日一次模式的较好窗口。真实每次交易会改变池价，可能提前关闭健康检查；此模型不能验证链上批量成交效果。

## 滚动窗口与验证

窄样例 10 个滚动 63 日配对的收益差中位数：NVDA -0.67 个百分点，TSLA/GME/AAPL 为 0。NVDA 有 2 个改善、7 个变差、1 个基本不变；其他股票也有正负变化，不能推出普适最优。

交易过程逐行调用 ledger，仅接收当行报价；没有用未来价格、没有根据结果选择参数。测试验证添加未来行不会改变过去的交易或状态。关闭新增循环时，96 个固定案例的收益与此前已复核 replay 的净值末点一致，最大差小于 0.000051 个百分点，仅为此前净值末点保留四位小数的舍入；旧版摘要收益保留三位小数，直接比较摘要的误差会稍大。

复现仅需 Python 标准库：

```sh
python3 -m unittest discover -s tests -p test_v2_cycle_backtest.py -v
python3 tools/v2_cycle_backtest.py
```

18 个测试通过；96 个固定配对、240 个滚动配对及固定窗口的批量敏感性均完成。机器结果为 `data/v2-cycle-results.json`，固定配对展开表为 `data/v2-cycle-results.csv`。结果 JSON 记录本次输入 fixture 的 SHA-256。审计修复后按原 Python 3.12.2 环境重放，两个冻结结果文件逐字一致；修复影响额外覆盖的小额止盈与最新止损组合边界。

**功能结论：** 简单循环可以减少一部分长期等待，并按一次受限回补关闭入口。**经济结论：** 更频繁回补也会恢复下跌风险和增加执行成本，当前样本不支持默认启用或宣称普遍改善；可作为明确选择的另一种固定策略 Kind。未部署、签名或进行实盘交易。
