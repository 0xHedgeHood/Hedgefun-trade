# V2 多人交易与开盘狙击实验

这四组实验在本地 EVM 中执行真实 V2 曲线、Factory、TradeRouter、Hook 和 V4 PoolManager。股票、喂价为测试替身；不是 Robinhood Chain Fork，也不广播交易。各钱包的交易在**同一时间戳逐笔排序**，用快照从相同初始状态重放反向顺序。EVM 没有“真正同时成交”；区块打包者决定实际排序。抢买、抢卖、交错场景比较 3 秒税窗结束后的普通交易；狙击场景另测开盘第 0、1、2、3 秒。

| 场景 | 可复现结果 | 含义 |
| --- | --- | --- |
| 四人抢买 | 各花 10 STOCK，先后到账 150,000、107,142.857、80,357.143、62,500 FUN；首位拿到末位的 2.4 倍。反转钱包顺序只改变归属，不改变合计成交和销毁。毕业边界的 1,000 STOCK 买单实际花 170、退 830；禁止部分成交时整笔回滚。 | 同时间戳的顺序有很大分配影响；前端必须明确最低到账和部分成交选择。 |
| 四人抢卖 | 曲线首位到账 1.1233、末位 1.0347 STOCK。毕业 V4 普通 10% 卖税下首位 7.9852、末位 4.8809；同规模四人共到账 25.2263。国库回购通知后，同规模卖单仍按 10% 税率、共到账 25.2263。 | 先卖者获得更好的价格；V2 已关闭回购触发的卖税峰值，通知不会改变到账。通知由测试中的授权国库身份触发，并非真实回购。 |
| 买卖交错 | 曲线卖家 A 在买单之后卖到账 2.1295 STOCK，买单之前卖只有 1.2958；毕业 V4 对应 10.8815 与 7.6931。 | 买卖双方同时间戳竞价，排序会改变实际结果；不能用单一静态报价代表区块内成交。 |
| 开盘狙击 | 曲线：机器人先买 20 STOCK、用户买 140、机器人同秒卖出。在第 0/1/2/3 秒，机器人净收益分别是 **−17.7589 / +30.8340 / +59.3687 / +78.1346 STOCK**。第 3 秒用户比先成交少拿 234,586.47 FUN。缩小机器人买单至 **0.1 STOCK** 后，第 1 秒用户虽设置未抢跑报价的 **99% `minOut`**，交易仍成交，用户少得 **0.2521%**，机器人净赚 **0.2972 STOCK**；机器人只买 **0.01 STOCK**、用户设置 **99.9% `minOut`** 时，用户少得 **0.0253%**，机器人仍净赚 **0.0298 STOCK**。第 2 秒两组分别净赚 **0.6797 / 0.0684 STOCK**。毕业 V4：机器人 5 STOCK、用户 20、机器人退出，净赚 **0.6819 STOCK**，用户少拿 1,023.34 FUN；10/30 时机器人净赚 2.8620 STOCK。以未抢跑报价设置 99% `minOut` 时，5/20 用户交易回滚，机器人单独往返亏 0.9545 STOCK。 | 99%→69.34%→39.67% 的开盘买税（10% 普通税下；税窗持续完整 3 秒，逐秒向普通税线性下降并向上取整）只让 20/140 样例在第 0 秒亏损；第 1、2 秒仍可夹击。收紧 `minOut` 可以限制单笔损失，却不能保证夹击无利可图：机器人可以缩小抢跑交易，让用户交易仍满足限滑。税窗结束后恢复普通曲线风险。 |

狙击净收益按机器人最终收到的 STOCK 减去其买入投入计算，包含测试中的买卖税和池内价格影响，**不包含 gas、优先费、builder 支付、外部对冲或 MEV 竞争成本**。因此它说明存在合约层面的有利排序，不是可兑现收益保证。开盘买税按完整 STOCK 买单推进曲线价格，然后销毁买家的一部分 FUN；受害者的高税并不减轻其买单造成的推价，机器人可在其后卖出。所有买家（包括创建者）支付相同税率；第 0 秒的普通用户也只拿到未税出币量的约 1%。V2 毕业创建 V4 池时只有普通 10% 税；不会重新启动开盘买税。毕业池固定 `spikeBps = 0`，国库回购通知也不会提高卖税。抢买、抢卖与交错场景部分交易是在执行前即时重新报价，尚未覆盖固定 calldata 的过时报价或公开 mempool 排队；狙击场景才对照了未受攻击报价下的固定 `minOut`。

复现：在仓库根目录运行 `python3 -m lab.server`，打开 <http://127.0.0.1:8765>，点击页面下方四个实验按钮。每次点击都启动对应的白名单 Foundry 测试，并显示本次成交数据与原始日志。也可以直接运行：

```bash
forge test --match-path test/V2MarketBuyScenarios.t.sol -vv
forge test --match-path test/V2MarketSellScenarios.t.sol -vv
forge test --match-path test/V2MarketMixedScenarios.t.sol -vv
forge test --match-path test/V2MarketSniperScenarios.t.sol -vv
```

目前结论：这些场景测试可作为交易顺序和安全回归测试；**开放真实开盘前仍有狙击风险阻断项**。3 秒买税是成本，不是公平排序或夹击防护的充分条件；1% 甚至 0.1% 限滑也不能保证机器人无利可图。下一步需要评估开盘批量统一价格、限滑与私有提交组合、以及更深的初始曲线等方案，并在真实 Robinhood Fork、更多交易规模和区块排序假设下复测。实验并未枚举所有攻击路径，也不是外部安全审计。
